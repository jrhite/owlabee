PACER RSS Feeds: Monitor New Federal Court Filings

Every federal district and bankruptcy court running CM/ECF publishes a free RSS feed of its last 24 hours of docket activity. This Actor reads those feeds for the courts you choose, normalizes each entry, filters it, and on scheduled runs keeps only entries that are new since the last run. No PACER account is needed.

The source and its limits

The feeds are the courts' own public endpoints, https://ecf.<court>.uscourts.gov/cgi-bin/rss_outside.pl. Each entry has the case number, the case title (the lead parties), the docket text, the document number with a link, and the filing time. Documents are linked, never downloaded; opening a document on PACER is subject to PACER's own fees.

Coverage differs per court. In the Actor's sweep of 2026-10-17, 94 courts published every entry type, 41 published a subset (typically complaints, motions and orders), 23 answered with no entries, and 30 did not answer datacenter requests. The Actor still tries every court you name and reports what happened. The full list is on PACER RSS feeds by court.

For past dockets, the optional historical pass reads the RECAP archive through the Free Law Project's CourtListener API, in the same record shape with source: "courtlistener-recap".

Limits worth knowing

  • Each feed covers the trailing 24 hours only. Schedule at least daily; hourly is a good default, since courts regenerate feeds every 30 to 60 minutes.
  • Nature of suit, party lists, judges and the full docket text are not in the feeds. The case title carries only the lead parties, so a party that is not first-named may be missing.
  • entryTypes is a heuristic over the entry text; use entryKeywords for precision.
  • The CourtListener API allows 5 requests per minute, 50 per hour and 125 per day by default, shared by anonymous callers; a free CourtListener token gives a run its own allowance.

Use cases

New cases naming a company

Combine partyKeywords, entryTypes: ["complaint"] and newCasesOnly to catch a new case opened against or by a company in the courts you watch.

Chapter 11 filings

Watch deb and nysb with bankruptcyChapters: ["11"] and onlyNewSinceLastRun on an hourly schedule.

Follow one case

Pass caseNumbers to get every new motion and order in a case without checking the docket by hand.

How to run it

You need an Apify account and its API token (Console → Settings → API & Integrations). Each run is billed per result to your account; set a maximum total charge for the run to cap spend.

With curl

The sync endpoint starts a run, waits up to 300 seconds and returns the dataset items. New Chapter 11 entries in the Delaware and Southern District of New York bankruptcy courts, new since the last run:

export APIFY_TOKEN=<your Apify API token>

curl -sS -X POST \
  "https://api.apify.com/v2/acts/owlabee~federal-court-docket-monitor/run-sync-get-dataset-items" \
  -H "Authorization: Bearer ${APIFY_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
  "courts": [
    "deb",
    "nysb"
  ],
  "bankruptcyChapters": [
    "11"
  ],
  "maxEntriesPerCourt": 25,
  "maxResults": 25,
  "onlyNewSinceLastRun": true,
  "stateStoreName": "pacer-chapter-11-de-sdny-monitor",
  "notifyOnlyOnResults": true
}'

FAQ

Do I need a PACER account?

No. The RSS feeds are public, unauthenticated endpoints. Only opening a linked document on PACER is subject to PACER's fees.

How far back does it go?

The live feeds cover 24 hours. Turn on includeHistorical to also read dockets from the last 1 to 365 days in the RECAP archive. That needs a free CourtListener API token in courtListenerApiKey, since the CourtListener API no longer answers anonymous requests.

Why does the same entry appear twice?

Some courts attach two event labels to one entry. Both are published with the same entryId; entryKey tells them apart.

Can I get the judge or all parties?

Not from the feed. Open docketUrl on PACER. Historical RECAP records do include parties, nature of suit and the assigned judge when the archive has them.

What if a court's feed is down?

That court produces one error item and the run continues with the others.
