Grants.gov API: Federal Grant Opportunities as JSON

Grants.gov is the federal government's listing of grant opportunities, and it has a public API that needs no key. This Actor searches it by keyword, normalizes each opportunity, and on scheduled runs reports only what is new or changed.

The source and its limits

The Grants.gov API lists federal grant opportunities with the statuses forecasted, posted, closed and archived. The Actor searches it for each keyword and, with fetchDetails, calls Grants.gov's fetchOpportunity for each result to add award ceiling and floor, expected awards, total funding, eligibilities, funding categories and the agency contact. No key and no login are needed.

The same Actor can add recent USAspending.gov awards for the same keywords (who won similar grants and contracts), and SAM.gov contract notices, covered on the SAM.gov page. Every record has the same core fields, so one feed can hold all of them.

Limits worth knowing

  • Grants.gov OR-matches the words of a keyword: "small business" matches "small" or "business". Use specific phrases.
  • postedWithinDays (1 to 365) applies to the Grants.gov open date.
  • Requests are limited to two per second per host, with backoff on errors. Each keyword on each source has a 10-minute budget.
  • When the agency set no award ceiling, awardCeiling is null rather than a guess.

Use cases

Grant alert feed for a program area

Schedule a keyword search with onlyNewSinceLastRun. Unseen opportunities arrive with isNew: true; ones whose title, status, dates or award fields changed arrive with isUpdated: true.

Forecasts before they post

Add forecasted to oppStatuses to see opportunities agencies have announced but not yet opened.

Who won similar awards

Turn on includeRecentAwards to add USAspending award records (recipient, amount, award type, dates) for the same keywords.

How to run it

You need an Apify account and its API token (Console → Settings → API & Integrations). Each run is billed per result to your account; set a maximum total charge for the run to cap spend.

With curl

The sync endpoint starts a run, waits up to 300 seconds and returns the dataset items. Posted and forecasted grants for two keywords from the last 30 days, with details, in monitor mode:

export APIFY_TOKEN=<your Apify API token>

curl -sS -X POST \
  "https://api.apify.com/v2/acts/owlabee~grants-gov-api/run-sync-get-dataset-items" \
  -H "Authorization: Bearer ${APIFY_TOKEN}" \
  -H "Content-Type: application/json" \
  -d '{
  "keywords": [
    "rural broadband",
    "digital equity"
  ],
  "sources": [
    "grantsGov"
  ],
  "oppStatuses": [
    "posted",
    "forecasted"
  ],
  "postedWithinDays": 30,
  "maxResults": 200,
  "fetchDetails": true,
  "maxDetails": 100,
  "onlyNewSinceLastRun": true,
  "stateStoreName": "broadband-grants-state"
}'

FAQ

Do I need a Grants.gov API key?

No. Grants.gov needs no key. Only the SAM.gov source needs a free personal key.

How does "only new or updated" work?

For every source and keyword the Actor stores a fingerprint per opportunity in a named key-value store. Unchanged opportunities are skipped and not charged. Change stateStoreName to start over.

Can it rank opportunities for my organization?

Pass the results to the Grant Matching and RFP Bid/No-Bid Scorer, which scores each record against a profile you describe once.

Does it scrape the grants.gov website?

No. It uses the official public APIs only, with no HTML scraping, proxies or login.

Are state and local grants included?

No. The optional sled source reads six state and local procurement datasets (bids, not grants); it is not a nationwide state and local feed.
